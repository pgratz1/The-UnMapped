## Advisories

**A1. A secession read apart from its crisis would found a second ruler line** (`figures.cpp:414-427`, `:492-507`). The link between a `succession_crisis` and the `civ_seceded` citing it is found only within one `read_log` range. If the two were ever appended in different steps (or figures ran between them), the secession would fall to the `on_founded` guard: reign (c2, 1) would be drawn there and a founder named with a `came_to_rule`, and the crisis would be treated as a non-split one (an exile draw). The output stays deterministic, but it would change silently with a subsystem's order or step. Today peoples writes both in one call, so it cannot happen. Proposed fix: have `on_crisis` (or the guard) check the secession's causes against the crisis whatever the range, for example by remembering crises read without a found secession in a small id set; or add a test that fails if a `civ_seceded` citing a crisis is ever read in a later range.

**A2. Book titles have no length bound in their numbered fallback** (`figures.cpp:1329-1334`). The tower fallback refuses a name past `NAME_MAX_BYTES` (`:1258`); the book loop appends `" " + roman(j)` without that test, so with a long data title and a full registry a title could exceed what the reader's checks or later stages assume. It is deterministic and terminates (the registry is finite), so not blocking. Proposed fix: the same `NAME_MAX_BYTES` fatal check as the tower loop.

**A3. `split_bonus_permille` reads the year of the figures' last step** (`figures.cpp:331-341`). The bonus that peoples adds to a split chance in its T4 depends on `year_`, set when figures last ran (its T3 of the same year, or the previous step). This is as spec 7.4 states and identical on every platform, but it ties a peoples value to the engine's subsystem order and step kinds: a peoples crisis drawn in a quiet step, or a reorder of `config.subsystems`, would change it without any key changing. Proposed fix: pass the crisis year (the step's `ctx.year()`) through the view, `split_bonus_permille(civ, year)`, so the value depends only on stored state and the caller's year.
